# Product Scope

## V1 Rebuild Must Have

### User And Context

- Signup, login, logout, password recovery path
- Preferred name
- Target role
- Target company
- Job description capture
- Resume upload and a place to store derived resume/context data

### Practice

- Que as the in-app interview coach
- Four active practice modes:
  - First Impression
  - Coaching
  - Rapid Fire
  - Mock Interview
- Question type selection for modes that need it
- Interview style selection
- Voice session launch
- End-session handling

### Feedback

- Transcript capture or final transcript artifact
- Post-session review
- Score dimensions:
  - Confidence
  - Clarity
  - Relevance
  - Impact
  - Authenticity
- Coaching insight
- Recommended next practice action

### Progress

- Session history
- XP and levels
- Rolling stat summary
- Streak foundation
- First useful Up Next behavior

### UX Quality

- Mobile-first app shell
- Clear empty states
- Clear microphone/session readiness UI
- Accessible names for all important controls
- Visible feedback for save, loading, success, failure, and session completion

## Improve During Rebuild

- Reduce onboarding friction by distinguishing required setup from optional
  personalization.
- Make the first practice session the most obvious next action.
- Make the pre-session flow visibly step-based and easy to backtrack.
- Make post-session feedback feel supportive and actionable rather than graded.
- Give story preparation and job context clearer roles in the product.
- Make desktop usable instead of merely stretched mobile.

## Can Wait Until After First Coded Beta

- Full Bubble feature parity if a feature is not needed to validate the core
  practice loop
- Industry packs
- Rich debrief voice mode
- Advanced quest types
- Advanced analytics dashboards
- Multi-role/team features
- Native mobile apps
- Replacing VAPI with our own realtime voice orchestration

## Existing Bubble Ideas To Preserve

- The four active practice modes
- Mode-specific step skipping
- Five locked score dimensions
- Session-specific snapshots of interview context
- Level thresholds and RPG-lite motivation
- Story library direction
- Saved job target direction

## Product Questions To Revisit

- Should resume upload be optional before first practice?
- Should the first session default to First Impression or let the user choose?
- Should job targets arrive in the first coded beta or the second pass?
- How visible should XP/quests be before a user has completed a session?
- Should every session show a transcript to the user, or only the review and key
  excerpts at first?
